# Project workflows for Codex

These are repository-local operating playbooks. They do not install personal/global skills. Apply `$reference-led-design` and the project's current capture tools. Preserve its existing working skill structure; incorporate the updated requirements where appropriate.

## Workflow 1 — Reference-to-presentation

**Input:** current repo, research sources, actual desktop assets.

1. Read the handoff contract and audit; inspect the references locally.
2. Inventory actual installed features and current theme tokens. Build a source→feature→shot map.
3. Implement three presentation candidates from ART_DIRECTION, using identical media for comparison.
4. Render on GitHub and in the Pages preview. Inspect real sizes, light/dark, mobile and navigation.
5. Select and refine the strongest candidate. Keep proof of the alternatives and reasons.

**Output:** chosen README/site layout, candidate comparison, exact asset/shot requirements. No fake desktop reconstruction or unlicensed reference footage.

## Workflow 2 — Capture-to-delivery

**Input:** approved user constraints, feature map, storyboard, existing `tools/showcase`.

1. Inventory owned state and prepare recovery; isolate demo windows and private content.
2. Confirm real animated wallpaper and scoped 0.78 opacity. Rehearse raw capture settings.
3. Record complete actions with bounded readiness waits. Keep immutable uncut source takes.
4. Assemble the film and feature clips using an edit manifest. Choose deliberate poster frames.
5. Compare encoders on identical inputs, including sparse purple preservation. Inspect final motion.
6. Restore state and verify cleanup. Record explicit pending gates honestly.

**Output:** public-safe media, source lineage, encoding commands, playback review and restoration evidence.

## Workflow 3 — Publish-and-verify

**Input:** complete candidate, current session's GitHub authorization, verified media manifest.

1. Check public content for private data and correct asset-credit scope before upload.
2. Render the README on a review branch; build only intended Pages files. Keep alpha.1 immutable.
3. Use supported hosting/upload routes and exact returned URLs. Verify actual attachment/Pages behavior.
4. Run link, layout, keyboard, reduced-motion and hosted-video checks. Confirm no fallback black rectangles.
5. Publish within existing authorization; if final publication is not authorized, deliver the complete concrete candidate for that decision.
6. Return the gallery first, then the concise results and remaining limits.

**Output:** reviewable/published presentation with exact SHA, real links and honest status.

## Handoff after interruption

Read `showcase/revision-2/STATE.md`, this contract, the current branch diff and the latest media manifest. Identify whether staging is active before touching the desktop. Resume from the recorded stage; don't reset the layout, regenerate all assets, or repeat already-passed unrelated tests. A partial upload is not proof of successful publication.
