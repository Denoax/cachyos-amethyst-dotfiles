# Acceptance and delivery

## Separate outcomes

Track four states independently: implementation, visual review, motion review and publication. A passing build is not visual approval. A new public page is not a stable desktop release. Mani's rejection of the first showcase is not approval of this revision.

## Required checks

| Area | Passing evidence |
| --- | --- |
| Reference inspection | Actual local inspection of all six Quickshell videos, Konata, Caelestia, end-4 and Hyprland references; adaptation decisions recorded |
| Candidate exploration | Three rendered layouts using comparable real footage; screenshots and reasons for selection; no invented scores |
| Wallpaper | Visible animation throughout desktop footage and behind VS Code/Dolphin/Discover; no hidden static/plain substitution |
| Theme | Current exact amethyst survives GIF/video conversion; black/white hierarchy preserved |
| Film | Coherent complete sequence, readable settled states, no accidental menus or setup prompts |
| Motion | Continuous 1× playback of all final clips; three loops per loop asset; actual observer/method recorded |
| Window behavior | Gather/restore works as described; terminal-group toggle has no observed geometry oscillation or duplicate children |
| Coding | Official VS Code; real C++23 GCC compile/run/debug; templates and input workflows; actual Python/Java outcomes; readable content |
| Daily integration | Only demonstrated working flows claimed; Discover catalog and Flatpak launch are distinguished |
| README | Actual GitHub rendering, light/dark, usable narrow layout, correct image scale and functioning links |
| Pages | Desktop/mobile, keyboard, 200% zoom, reduced-motion behavior, pause/fullscreen, deep links, no media load errors or unwanted audio |
| Integrity | Media checksums, source/encode lineage, real captions, no private content in public assets |
| Restoration | Staging diffs restored, original editor intact, no leaked owned jobs, runtime still healthy |
| Compatibility | Existing alpha and failed/pending portal/laptop/fresh-login claims remain accurate |
| Publication | Exact candidate SHA/deployment/media URLs checked, old alpha.1 preserved, no stale README links |

## Quality review rubric

Use a 1–5 score per category only after rendered review; attach a short reason and the view/clip checked. Categories: immediate impact, wallpaper continuity, readability, interaction clarity, motion quality, feature breadth, consistency, mobile usability and truthful scope. A missing or broken core interaction is a failure regardless of average score. Scores document judgment; they are not objective performance measurements.

Fix observed defects and rerun the affected checks. Don't repeatedly run installer tests for pure poster changes. If editing installer/configuration code becomes necessary, run its relevant regression checks and explain the scope separately. Presentation-only work should not destabilize the distribution.

## If continuous review is unavailable

Complete the site, media encodes, layout comparisons, integrity checks and restoration. Supply the exact playable candidate and a focused review task: full film plus named loop seams. Report `MOTION_REVIEW_PENDING`, not `PASS`, and do not call it a finished polished showcase. Do not remove the wallpaper to escape this gate. Do not block independent work while waiting for feedback.

## Return to Mani

Deliver a short `CODEX_RETURN_SHOWCASE_V2.md` with:

1. Best playable gallery/film link first, followed by the rendered GitHub README.
2. Chosen layout and why; links to the other two concrete alternatives.
3. What changed in framing, coverage, encoding and wallpaper continuity.
4. Exact branch/SHA and deployment/release status; unchanged alpha.1 reference.
5. Test/review results with pass/fail/pending, including the observer for motion.
6. Remaining limitations and any targeted user review needed.
7. Confirmation and evidence of live-session restoration.
8. A review bundle with the manifest, screenshots, final optimized media, source/credits and reproducible commands; no raw wallpaper or private captures.

Final prose should describe the outcome, not overwhelm Mani with internal process. Link technical evidence for inspection. Do not claim an approval that hasn't happened.
