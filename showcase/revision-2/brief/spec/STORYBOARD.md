# Film and feature coverage

## Master film — target 80 seconds

The timing is an editorial starting point. Preserve complete visible actions and enough settled time to understand them. Capture longer uncut takes, then edit the film. Every on-screen success must come from the corresponding real workflow.

| Time | Scene | Action and framing |
| --- | --- | --- |
| 00–06 | Identity | Actual animated wallpaper and rail; slim Amethyst title appears briefly, then clears. No static intro card replacing the desktop. |
| 06–15 | Navigation | Launcher opens, purposeful search selects an app, panel closes; show visual window selection. Use current bindings, not old Kona assumptions. |
| 15–24 | Window control | Gather windows with Super+D, hold, restore. Show the terminal group with Super+Shift+D, settled and without shaking. Separate takes if monitor context needs explanation. |
| 24–46 | Coding | Official VS Code: create problem from shipped template, build/run a real C++23 example, inspect output, pause at an informative breakpoint. Wallpaper moves behind the 0.78-opacity window. |
| 46–54 | Languages | Brief genuine Python and Java runs with readable results; exact versions go in a caption/manifest, not giant on-screen terminal dumps. |
| 54–65 | Daily applications | Dolphin navigation and Discover's verified Flatpak source/app; launch a known installed Flatpak. Preserve actual background. |
| 65–74 | Shell detail | Clipboard with harmless demo text, a real test notification, audio/media controls, shortcut guide. Keep each event legible; expand clip library if this segment is too dense. |
| 74–80 | Return | Close owned demo surfaces; return to the recognizable live desktop. Small credit/source action, no exaggerated performance claims. |

No music is necessary. If adding sound, use licensed/owned audio, supply a silent version, and keep browser audio off until requested. Do not capture incidental personal playback or copyrighted soundtrack just because it was on the PC.

## Focused clip library

Produce separate clips for desktop/rail, launcher, window picker, shortcut guide, gather/restore, terminal group, C++ build/run, C++ debugger, Python/Java workflow, Dolphin, Discover, Flatpak launch, clipboard, notification history/DND, and audio/media. Combine closely related features when the result is clearer. Capture dashboard/session/lock/screenshot flows only after verifying they work safely and match current product scope.

Each clip has: a clean starting state, one specific action, a readable result, and a resolved ending. Record the real shortcut in the manifest. Do not use unknown/guessed key bindings. A shortcut guide's contents should match the actual installed configuration.

### Special cases

- **Super+D:** show the actual intended gather destination and exact restoration; record window addresses/geometry privately. A single-output clip can show arrival but is insufficient proof of all-output restoration. Keep a private full-desktop evidence take or per-output before/after evidence, plus continuous action review.
- **Super+Shift+D:** run repeated open/close cycles before filming. If geometry oscillates, capture and repair the bounded helper behavior before using it as a headline feature. No timing edits that hide the shake. If the issue lies outside presentation scope, report the specific blocker and complete other chapters.
- **VS Code:** preserve the user's working editor. Use an isolated profile seeded from the actual exported settings/extensions. Dismiss onboarding and extension prompts before the take. Avoid misleading empty terminal panels and unrelated diagnostics. Demonstrate both saved input and interactive input across film/clip library, plus new-problem creation and sample/stress runner if present and verified.
- **Discover/Flatpak:** distinguish browsing a catalog from verified integration. Show the source/backend, open a real app detail, and launch an installed app. Do not imply PackageKit is a replacement for supported CachyOS system-update procedures. Avoid triggering a broad host upgrade solely for a video.
- **Clipboard/notifications:** use demo content in an isolated/staged context. Don't expose or erase personal history. A test notification is allowed; fabricated CPU/FPS/benchmark results are not.
- **Audio/media:** controls changing visually are not proof of audible output or microphone capture. Label the demonstrated scope accurately.
- **Lock/session:** preserve authentication. Do not automate typing a password into a captured session or disable locking for the showcase. If safe lock/unlock cannot be reviewed, mark it pending and keep it out of verified feature claims.
- **Portals:** the prior report failed screen-sharing/Secret portal tests. Do not include a successful-looking sharing demo without new actual proof. Don't repurpose the recording tool's success as a portal pass.
